Design — context

Resources today are hard-deleted on DELETE. Three support tickets in the last quarter asked to recover deletes — each one cost ~2 hours of manual D1 restore work. The team agreed in the 2026-04-10 sync to move to soft-delete with a TTL.

Design — rationale

The cheapest "undo" we can give support staff. Existing D1 backup restores work but are manual and only catch deletes older than 24h. Soft-delete pushes the recovery window to the application layer where it's a 1-click action.

We considered a tombstone marker without TTL — but that grows the table indefinitely and SELECT * WHERE archived_at IS NULL won't perform well past ~100k rows. A 30-day TTL keeps the working set bounded and matches what other tools in the space do (Linear, Notion).

We're not building a "trash" UI yet. Restore is API-only for now; the admin UI gets a flag next sprint.

Decisions

DecisionRationaleAlternatives
Soft-delete via archived_at timestamp, not a separate table. Keeps queries simple, no JOINs across active/archived tables, and D1 row count growth is acceptable for expected scale. Separate archived_resources table Tombstone w/o TTL
30-day grace window, configurable via env var. Matches the longest support-ticket recovery delay seen. —
Block mutations on archived resources at the schema layer (ResourceUpdate). Cheapest enforcement point; covers all current and future routes uniformly. —

Rollback

The migration is additive — 0007_add_archival.sql only adds a column and a new enum value. To roll back: disable the Cron Trigger in wrangler.jsonc, redeploy; revert the route + schema changes (PR revert); leave the column in place.

No data loss from rollback — archived rows remain queryable and will simply look like normal resources with archived_at populated.

If hard-delete has already fired for some rows: those are gone. PITR window for D1 (7 days) is the only recovery path.

Spec delta — resource-archival

Added

Archive a resource
Soft-deletes a resource by setting archived_at to now and the status to ARCHIVED. Hidden from list endpoints unless include_archived=true is passed.
Archives an active resource
  • GIVENa resource with status ACTIVE
  • WHENPOST /resources/:id/archive is called
  • THENstatus becomes ARCHIVED
  • ANDarchived_at is set to the current timestamp
  • ANDthe resource no longer appears in GET /resources without include_archived
Archiving an already-archived resource is a no-op
  • GIVENa resource with status ARCHIVED
  • WHENPOST /resources/:id/archive is called
  • THENthe original archived_at is preserved
  • ANDa 200 OK is returned (idempotent)
Restore an archived resource
Returns an archived resource to ACTIVE before the 30-day TTL fires.
Restores within the grace window
  • GIVENa resource with status ARCHIVED and archived_at within 30 days
  • WHENPOST /resources/:id/restore is called
  • THENstatus becomes ACTIVE
  • ANDarchived_at is cleared to NULL
Block mutations on archived resources
PATCH on archived resource is rejected
  • GIVENa resource with status ARCHIVED
  • WHENPATCH /resources/:id is called with a valid ResourceUpdate body
  • THENa 409 Conflict is returned with detail 'resource is archived'
  • ANDno fields are persisted

Modified

List resources
GET /resources gains an include_archived query parameter. Default false — existing callers see the same result set.
